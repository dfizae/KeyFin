# 핀테크 도메인 보안과 정합성

이 규칙은 `50-error-security.md`에 더해 금융 서비스 특성에 따라 추가로 적용한다. 충돌 시 이 규칙이 우선한다.

## 금액과 숫자

- 금액은 JavaScript `number`로 계산하지 않는다. 서버는 원 단위 정수를 JSON number 로 내려주므로(규칙 90) `features/<domain>/model.ts`에서 `lib/money.ts`의 `fromServerWon`으로 `KRW` 문자열로 바꿔 보관하고, 합산·비교가 필요하면 `lib/money.ts`의 정수(원 단위 `bigint`) 유틸만 사용한다.
- 금액 표시는 `lib/money.ts`의 포맷터(`formatKRW` 등)만 사용한다. 컴포넌트에서 `toLocaleString`을 직접 호출하거나 콤마를 문자열 조작으로 넣지 않는다.
- 금액 입력은 `AmountInput` 컴포넌트를 사용하고 숫자 키패드(`keyboardType="number-pad"`)를 지정한다. 입력값은 문자열 상태로 유지하고 제출 시에만 검증·변환한다.
- 통화 단위(KRW), 부호, 마스킹 여부는 표시 계층에서 결정한다. 서버 DTO를 화면에서 직접 가공하지 않고 `features/<domain>/model.ts`에서 화면 모델로 변환한다.
- 소수점이 있는 통화나 환율을 다루게 되면 소수 자릿수 규칙을 `lib/money.ts`에 먼저 정의하고 사용한다.

## 이체·결제 요청

- 이체, 결제, 출금 등 돈이 움직이는 mutation의 중복 실행은 서버가 기관거래고유번호로 막는다(KeyFin 계약에는 `Idempotency-Key` 헤더가 없다, 규칙 90). 클라이언트는 같은 제안 id로 승인·재시도를 보내고, 새 요청을 만들어 내지 않는다.
- 돈이 움직이는 mutation은 자동 재시도(`retry`)를 하지 않는다. 네트워크 오류 시 "처리 여부를 확인 중"임을 안내하고 서버 상태 조회(`GET /transfers`의 해당 id 상태)로 결과를 확정한 뒤 다음 행동을 제시한다.
- 제출 버튼은 요청 시작 즉시 비활성화하고 `isPending` 동안 중복 탭을 막는다. 뒤로가기·앱 전환으로 화면이 사라져도 요청이 중복 발생하지 않도록 한다.
- 확인 화면에는 받는 사람, 계좌(마스킹), 금액, 수수료, 예상 도착 시점을 모두 표시하고, 사용자가 명시적으로 확인한 뒤에만 인증 단계로 넘어간다.
- 딥링크나 푸시로 이체 파라미터가 들어오면 검증 후 반드시 확인 화면을 거친다. 파라미터만으로 이체를 실행하지 않는다.

## 인증과 세션

- 액세스·리프레시 토큰, PIN 검증 결과, 기기 바인딩 값은 `expo-secure-store`에만 저장한다. AsyncStorage, Zustand persist, 로그에 저장·출력하지 않는다.
- PIN은 6자리, 입력 화면은 `PinPad` 컴포넌트를 사용하고 서버 검증 실패 횟수를 표시한다. PIN을 클라이언트에 평문으로 보관하지 않는다.
- 생체인증은 `expo-local-authentication`으로 처리하고, 실패·미등록 시 PIN으로 폴백한다. 생체인증 성공 자체가 서버 인증을 대체하지 않는다.
- 앱이 백그라운드로 가면 잔액·거래 화면을 가리고(앱 스위처 스냅샷 대응), 설정된 시간 이상 지나면 재인증을 요구한다.
- 인증이 필요한 화면은 인증 상태를 라우트 그룹(`app/(auth)`, `app/(app)`) 레이아웃에서 검사하고, 개별 화면에서 흩어져 검사하지 않는다.

## 민감 정보 표시와 로깅

- 계좌번호, 카드번호, 주민번호, 전화번호는 기본 마스킹으로 표시하고, 전체 노출은 명시적 "보기" 액션과 인증 뒤에만 허용한다. 마스킹 유틸은 `lib/mask.ts`에 둔다.
- 오류 리포팅, 분석 이벤트, 콘솔에 금액, 계좌번호, 이름, 토큰, 요청·응답 본문을 포함하지 않는다. 필요한 문맥은 거래 ID와 오류 코드로 한정한다.
- 잔액·거래 내역·인증 화면에서는 스크린샷·화면 녹화 방지 적용을 검토하고, 적용 여부를 보고서에 명시한다.
- 클립보드에 계좌번호를 복사하는 기능은 사용자의 명시적 액션에서만 수행하고 민감 정보를 자동으로 복사하지 않는다.

## 네트워크와 기기

- API 호출은 HTTPS만 사용한다. 인증서 고정(pinning) 적용 여부는 백엔드와 합의해 `api/client.ts`에서 한 곳에 적용한다.
- 루팅·탈옥 탐지, 에뮬레이터 탐지는 기능 차단이 아니라 위험 신호로 서버에 전달하고 정책은 서버가 결정한다.
- `EXPO_PUBLIC_` 환경 변수에는 API 베이스 URL 같은 공개 가능한 값만 둔다. 서명 키, 서버 토큰, 내부 URL을 두지 않는다.

## 시간과 상태

- 서버 시각은 계약 형식(시간대 없는 KST `YYYY-MM-DDTHH:mm:ss`, 날짜·시각 분리 필드, `YYYYMM`)으로 받고 `lib/date.ts`에서 `+09:00`을 붙여 파싱해 표시한다. 기기 시각을 거래 시각으로 사용하지 않는다.
- 거래·이체 상태(거래 `NORMAL`/`CANCELED`, 확정 `AUTO`/`PENDING`/`CONFIRMED`, 이체 `PROPOSED`→`APPROVED`→`EXECUTED`/`FAILED`/`CANCELED`)는 유니온으로 정의하고 상태별 UI를 빠짐없이 처리한다. 알 수 없는 상태는 오류로 처리하지 않고 `UNKNOWN`으로 흡수해 "확인 중"으로 표시한다.
